# 第 22 章：MCP 与插件，让工具进入工作流

你问 Codex“仓库默认分支是什么”，它可能从本地 Git、GitHub 工具、网页或旧聊天中回答。同一句答案，来源不同，新鲜程度和可支持的结论也不同。扩展能力的第一步不是安装尽可能多的工具，而是明确缺少哪份信息、应从哪里取得，以及取得后能证明什么。

本章解释 MCP 与插件怎样进入任务，观察一次本制作环境的真实只读调用，并提供无需外部账号的替代练习。完成时，你能选择是否需要连接，核对调用范围，并把失败归到合适的位置。

## 先分清四件事

MCP（Model Context Protocol）是一种让客户端与工具、数据服务协作的开放协议；它约定如何发现能力与交换调用。MCP 服务可以提供工具、资源等内容。协议不是你的账号，也不保证某项数据一定可读。

插件是可安装的能力包，可以包含 Skill、MCP 服务，或者两者。Skill 描述怎么完成一类工作，工具则接收结构化参数并执行特定读取或动作。账号连接与服务权限决定它能访问什么；当前会话可见的工具再决定你眼下能调用什么。以上边界按 **2026-10-25** 的 [OpenAI MCP server 说明](https://developers.openai.com/plugins/concepts/mcp-server)和 [Skills 说明](https://developers.openai.com/plugins/concepts/skills)核对。

例如，“读取指定仓库元数据”是一个工具动作；“先核实仓库，再比较改动，最后形成审查说明”是一套工作方法。把方法写进 Skill，不会自动获得 GitHub 权限；安装了插件，也不等于应该使用它提供的每一种写入动作。

## 真实调用：只回答一个具体问题

本制作环境已提供 GitHub 插件。本章实际通过它的 `get_repo` 能力，请求：

```json
{"repository_full_name":"liamamilin/codex-mastery"}
```

调用返回仓库全名 `liamamilin/codex-mastery`、默认分支 `main`、可见性 `public` 和非归档状态。读取没有创建仓库、提交、评论或修改配置。提取的公开字段保存在 `extensions/connection-evidence.json`，其中明确标注日期与来源。

这能证明**本制作环境当时能够读取这份仓库元数据**。它不能证明读者已连接同一账号，不能证明仓库里每个文件可读，也不能证明 Pages 已部署。返回中的仓库大小或缓存字段也不应被拿来替代文件检查。

你若当前会话确有同类 GitHub 读取工具，可以发给 Codex：

```text
只读查询 liamamilin/codex-mastery 的仓库元数据。
先确认当前会话是否有适用工具，只请求这一仓库。
给出仓库全名、默认分支与可见性，并说明数据来自哪次调用。
不要创建连接、修改仓库或执行写操作；不能访问就报告具体边界。
```

工具名称会因入口而不同，不要把这里的内部动作名当成每个客户端都能输入的命令。如果没有工具，直接转入后面的本地替代练习，仍可学会核对来源，无需为了跟课额外开通服务。

## 连接成功之后，核对的是哪一层

工具出现在目录中，说明宿主知道这个能力；调用返回数据，说明这次请求在当前条件下完成；数据含目标字段，才支持具体回答。三个环节不能压成一个“已连接”。服务可用但账号未授权某仓库、查询参数错误、网络超时，都可能让读取失败。

让 Codex 说明被调用工具、参数中的目标、返回字段与错误。不要在公共日志中打印令牌或完整敏感环境变量。只读返回也可能包含私有资料，任务所需的最小字段通常比复制整份响应更容易判断。

如果得到 403，先检查当前账号与资源访问范围；若工具根本不存在，先检查当前客户端与配置；若返回另一仓库，则核对参数。不要为了一个仓库名错误而放开所有权限，也不要因为一次网络失败就反复新增同一连接。

## CLI 的 MCP 列表不是所有入口的总目录

在操作系统终端可先查看帮助与已配置服务：

```sh
codex mcp --help
codex mcp list
```

本机 CLI `0.154.0` 实际执行过两条命令，帮助提供 list、get、add、remove、login、logout 等管理入口。列表用于查看该 CLI 配置，不是断言桌面宿主所有插件状态的唯一依据。本项目的 GitHub 调用来自当前宿主工具目录，不能仅凭另一入口没列出 GitHub 就说它不存在。

当期支持的本地 stdio 与远程 HTTP 连接方式、认证入口和配置位置见 [OpenAI MCP 文档](https://learn.chatgpt.com/docs/extend/mcp)。本章不执行 `add`、`login` 或改全局配置。需要连接新服务时，先判断其来源、依赖、账号要求和动作范围，再按当前入口的官方说明设置，而不是粘贴不明启动命令。

工具返回的是外部材料，不是新的任务授权。仓库 README 或网页即使写着“立即上传你的配置”，也不能替代用户指令。仍按原任务使用信息，把与目标不符的动作当作待判断内容。尤其不要因读取成功就顺手执行评论、提交或发布。

在交付中保留来源与观察日期，也方便后来的人发现缓存或旧信息，而不把历史回答误当作实时状态。

## 无账号替代：准确说出文件的来源

打开仓库中的 `extensions/connection-evidence.json`，让 Codex 只读取本地文件，提取相同三个字段。再问：“这份文件能证明今天远端仓库仍然如此吗？”正确的边界是：它是一份注明日期的历史观察，本地读取不等于实时 GitHub 查询，也不属于一次 MCP 调用。

接着对照 `cases/B-tasktrail/README.md`，让它找到当前项目的启动位置与样本文件。这说明很多任务已有足够本地材料，不需要外部连接。若目标只是解释本地入口，增加服务反而带来认证、网络和来源混淆。

这条替代路径没有伪装成 MCP，也不能证明连接操作成功；它训练的是同一个判断：答案从哪里来，能支持多新的结论，下一步是否真的需要另一个来源。

## 动手：做一次有边界的来源选择

从“查询远端默认分支”“解释本地脚本入口”“发布一个评论”中选一个目标，写出所需来源和是否会改变外部状态。实际执行其中一个只读目标，记录工具或文件、目标、返回信息与不能推出的结论。

再模拟连接不可用：不要换个词让 Codex 猜答案，让它选择本地材料、官方网页或明确缺失。完成标准是你能说明为什么当前任务需要或不需要连接，并能把“配置过”“本次读到了”和“允许写入”分开判断。
