# 第 12 章：把较大任务分成有价值的里程碑

“收藏工具还差标签、搜索、导入、备份和漂亮界面。”清单越写越长，Codex也一直在忙，但你至今没有一个可以安心保存链接的版本。把任务拆成许多动作，并不一定得到阶段成果；如果每一段都要等其它段才能使用，拆分只是换了一种列待办的方法。

本章回到 LinkShelf。你将为自己的版本确定三个里程碑，给每阶段写出可观察的完成状态，并推进当前最有价值的一段。终点是一条能够连续交付的路线，阶段结束时有实际文件、可运行入口与检查结果，而不是只有“第一阶段完成”的标题。

## 里程碑应该能被单独使用

“建立 HTML、写 CSS、补 JavaScript”可以是内部实施步骤，却不是普通使用者能判断的三个阶段。只有 HTML 的表单还不能保存，只有漂亮样式也不能找回收藏。若第一阶段结束时用户仍不能完成一件事，就值得重新考虑切法。

可以把第一阶段定义为“保存一条链接并在刷新后找回”。它可能同时涉及页面、事件与存储，但价值完整。第二阶段再解决“多条记录中找目标”，第三阶段解决“带走当前数据快照”。这些阶段各有独立使用行为，也保留了后续扩展的空间。

阶段不是必须同样长。一个下午解决基础路径、半小时增加搜索都合理。不要为了让表格对称，硬把同一条关键路径拆开；也不要因为最后可能有导入功能，就在第一阶段先建立复杂账户系统。

## 给 LinkShelf 一条三阶段路线

沿用自己的 `my-linkshelf`，先确认当前已实现什么。教材参考成品提供基础收藏、关键词搜索与 JSON 导出；**没有标签管理或重新导入**。下面是一条用于自己推进的路线，不能把表中的目标全当作你已经完成：

| 阶段 | 对使用者的价值 | 可观察的完成状态 |
| --- | --- | --- |
| 1 / 留得住 | 收好一条网页地址 | 新增可见，刷新仍在；删除后刷新不恢复；坏输入不保存 |
| 2 / 找得到 | 在多条收藏中定位 | 标题或网址关键词能缩小列表；清空搜索恢复；无匹配不删除数据 |
| 3 / 带得走 | 保留当前数据快照 | 导出真实 JSON；条目与当前收藏一致；下载结果可打开核对 |

这条路线刻意没有把“导出”写成“完整备份恢复”。没有导入，就不能承诺一键还原；JSON 文件只是可带走的备份材料。标签也是另一项后续能力，需要决定格式与筛选行为，不能因为你画了几个标签按钮就说已实现。

每一阶段还应保留已有检查。搜索上线后，新增和刷新仍须成立；导出上线后，搜索不能意外改变导出的数据范围。你可以选择只导出全部收藏，也可以另做筛选结果导出，但必须说明并验证。当前参考成品导出全部收藏，不因搜索关键词而丢掉未显示条目。

## 先核对起点，再选择当前阶段

向 **Codex 输入框**发出下面的调查任务，工作位置是自己的副本：

```text
请先检查当前 LinkShelf，按“留得住、找得到、带得走”
说明已有实现、实际验证与缺少的部分，不立即修改。
引用当前文件，不把教材参考成品的能力当成这个副本已有。
每阶段只写一条使用路径和必要边界，
指出最早尚未达到完成状态的阶段。
```

如果阶段 1 的刷新仍会丢记录，就优先修这一条，而不是被阶段 3 的下载按钮吸引。如果代码已有搜索但没检查空结果，应把状态写为“已实现、待验”，而不是重新安排一轮搜索开发。路线会因实际起点改变，数字编号只是便于交流。

接着选当前阶段发实施任务。例如阶段 2 尚未实现时：

```text
本轮只完成关键词搜索：按标题或网址匹配；
空关键词显示全部，无匹配有提示，搜索不得修改收藏。
保留新增、删除和刷新保存，不做标签或导入，不增加后端。
请完成可运行文件，说明怎么启动，并给出两条记录的验收动作。
代码检查与真实浏览器操作分别记录。
```

这里没有要求先完成全部三个阶段才能交付。阶段 2 做到以后，你就有一个比阶段 1 更有用的产品；若阶段 3 暂时受阻，已有成果仍可以使用。每阶段都能形成一个自然的停靠点，这正是分阶段带来的实际收益。

## 让阶段验收覆盖相邻行为

在自己的页面新增“里程碑12·学习资料”与“里程碑12·项目主页”两条样本。搜索“里程碑12·学习”，本轮两条中应只显示第一条；搜索一个确认不在现有收藏中的词，列表应出现无匹配提示；清空搜索，两条都回来。若已有相同前缀的旧样本，换一个新的前缀，避免把旧匹配误判为失败。最后刷新并确认记录仍在，再删除本轮其中一条、刷新确认只删了目标。

这些动作不仅检查新搜索，还保护原存储路径。没有第二条记录，就很难区分正确筛选与“简单清空”；没有清空搜索，就不知道隐去的记录是否还能回来。最有价值的回归通常围绕相邻行为，不需要为了一个搜索框重建庞大测试系统。

阶段 3 则应该实际检查下载文件，而不只看按钮动画。打开 JSON，比较条目与页面总收藏；文件保存位置由浏览器决定，网页发起下载不能证明已经落到某个固定目录。导出后不要立刻清空原收藏来试恢复，因为本阶段没有导入。这项验收由你亲自进行，不会因教材展示了一个下载按钮就自动通过。

## 怎样留下足够的阶段状态

可以在自己的副本中保存几行 `milestones.md`，或沿用已有 `progress.md`：当前可用阶段；实际运行入口；这次通过的动作；未通过与未检查；下一段目标。不要再创建五份内容重复的状态表。

例如“阶段 2 已有代码；搜索与清空实际通过；删除后刷新未验；先补这项，再进入导出”比“搜索完成 90%”更能指导下一次行动。百分比没有说明缺的是关键行为还是颜色微调。阶段是否完成，应由预先写出的行为与证据支持。

若新事实使某阶段太大，就把它重新切成有用结果。标签可以先只记录、再筛选，但前一段是否对使用者有价值仍要判断；导入可以延后，不要靠把按钮设为禁用来假装已经交付。必要时缩小当前承诺，保存可用部分，下一章会继续讨论途中判断。

## 动手练习：改写一份只有内部动作的计划

把“搭页面 → 写样式 → 写存储 → 测试 → 上线”改成适合自己 LinkShelf 的三个里程碑。每个阶段写一句用户行为、一条关键边界、一项检查。然后只选择当前最早缺少的一段执行，不要求今天把全部功能做完。
