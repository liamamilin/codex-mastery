# 第 2 章：建立可操作的工作环境

你输入了 `codex`，电脑却说找不到命令；换到 App 之后，它又找不到案例文件。两个问题表面上都像“Codex 用不了”，实际分别发生在命令入口和工作位置。环境准备的价值，就是把这类问题变成可以逐项确认的事实。

本章的完成状态是一段简短记录：你使用哪个入口、Codex 的版本是什么、当前工作目录在哪里、它能读到哪个案例文件，以及当前允许它做什么。这里不要求修改任何教材文件。安装需要网络和电脑上的安装权限；使用 Codex 还需要可用账号与相应访问权限。没有账号访问时，仍可先运行第 3 章参考成品，实际 Codex 协作练习留待条件具备后完成。

## 先找到自己的位置

打开 macOS 的“终端”，或 Windows 的 PowerShell。终端中接收命令的程序叫 shell。它有一个“当前目录”：相对路径以这里为起点。`cases/A-linkshelf` 并不是电脑上唯一的位置，它只有在教材根目录下才指向我们的案例。

先在文件管理器找到下载并解压的教材文件夹，复制它的完整路径。下面的路径是**需要替换的示例**。不要把书作者电脑的目录照搬到自己的机器。

**macOS / Linux，在操作系统终端输入：**

```sh
cd "/你的实际路径/codex-mastery"
pwd
ls
```

**Windows，在 PowerShell 输入：**

```powershell
Set-Location "C:\你的实际路径\codex-mastery"
Get-Location
Get-ChildItem
```

第一条改变当前位置，第二条把位置显示出来，第三条列出这一层的内容。成功的观察是：路径确实指向你解压的教材，并且列表里同时出现 `book`、`cases` 等文件夹。路径两侧的引号让带空格的目录仍被当作一个参数。文件夹名称可能带下载分支后缀，以你实际看到的为准。

如果出现“找不到路径”，先比较文件管理器中的名称、层级与命令。不要新建一个同名空目录来让报错消失，否则下一步虽然能进入，案例仍然不存在。路径问题应该通过找到正确对象解决。

## 选择一个能启动的 Codex 入口

先在操作系统终端执行下面两条，它们只查看程序信息，不要求登录：

```sh
codex --version
codex --help
```

若能显示版本与帮助，说明终端已经能找到 Codex，可以跳过安装。若提示找不到命令，才需要安装或检查命令位置。`--help` 是你当前程序的说明，尤其适合判断书中的参数在本机是否存在。

官方 CLI 页面同时提供独立安装器与 npm 等安装方式，并说明从项目目录启动 `codex`。[Codex CLI 官方文档](https://learn.chatgpt.com/docs/codex/cli)于 2026-10-25 核对。本书下面选择 npm 路线，是为了让具备 Node.js 的读者使用一条常见路径；它不是使用 Codex 的唯一条件。

先运行：

```sh
node --version
npm --version
```

两条都有版本输出，表示 Node.js 运行时和 npm 包管理器可用。本书制作机器使用 Node.js `22.21.1`；这是一条实测记录，不表示 CLI 永久要求这个精确版本。若任一命令不存在，先从 [CLI 官方安装页](https://learn.chatgpt.com/docs/codex/cli)选择适合系统的独立安装器，或安装 Node.js 后重新打开终端。不会安装 Node.js 的读者采用官方独立安装器，通常能少引入一个当前不需要学习的工具。

**仅在决定采用 npm、且上面的检查可用时，于操作系统终端执行：**

```sh
npm install -g @openai/codex@latest
codex --version
```

此命令安装全局可执行程序，会从网络下载软件；`latest` 随时间变化。官方 [Codex Cookbook](https://developers.openai.com/cookbook/examples/codex/using_goals_in_codex)仍列出这一 npm 安装方式；[Windows 部署文档](https://learn.chatgpt.com/docs/enterprise/windows-deployment)也包含 npm 路线。安装报权限错误时，先记录错误与安装位置，按官方指导选择用户可写的安装方式。在组织管理的电脑上，沿用管理员允许的路径即可。

Windows PowerShell 若提示脚本执行被策略阻止，可先尝试 `npm.cmd --version`，可用时将上述安装命令的 `npm` 改为 `npm.cmd`。通过 npm 安装的 Codex 也有脚本启动入口；遇到同类拦截时，将后文操作系统命令中的 `codex` 改为 `codex.cmd`，例如 `codex.cmd --version`、`codex.cmd login`。如果组织策略仍不允许执行，使用其批准的安装方法。Windows 原生终端与 WSL2 是不同环境；装在其中一个环境的程序不等于另一个也已安装。已有 WSL2 工作流的读者可参考[官方 WSL 指南](https://learn.chatgpt.com/docs/windows/wsl)，在其 Linux 终端中操作，并使用 Linux 路径。

## 登录与启动是两件事

安装成功后，在教材根目录的终端输入：

```sh
codex login
```

按实际界面完成浏览器登录，再回到终端检查：

```sh
codex login status
```

官方目前区分 ChatGPT 登录和 API Key 登录，两者访问与计费方式不同；本书入门采用已有 ChatGPT 账号的交互登录路径。可用权益取决于账号和工作区，不因安装完成就自动获得。[官方身份验证说明](https://learn.chatgpt.com/docs/auth)列出了这些差异。不要为跟随前三章额外开通 API 付费；遇到访问限制，先确认当前账号的可用范围。

`codex login status` 能报告登录方式，不能证明每个模型、每项工具都能调用。这里也不要把凭据文件内容粘贴给模型。我们只需要状态信息，账号密钥不会帮助定位教材目录。

接下来启动交互会话：

```sh
codex --sandbox read-only
```

`read-only` 为这次调查选择只读沙箱。沙箱（sandbox）规定执行可访问与修改的边界；审批策略则决定哪些动作需要额外确认，两者共同影响实际行为。[官方沙箱文档](https://learn.chatgpt.com/docs/sandboxing)说明了两者的关系。组织或宿主的管理策略也可能限制最终权限，以会话实际显示为准。

进入 Codex 以后，在它自己的输入框输入 `/status`，查看工作位置和当前配置。斜杠命令属于 Codex，不能在普通 shell 提示符下代替 `pwd`。随后发送这段自然语言：

```text
请确认当前工作目录，只读检查 cases/A-linkshelf/starter/TASK.md
是否存在，并用两句话概述任务。不要创建或修改文件，
不要安装依赖。请说明你实际读取的是哪个路径。
```

完成标准是：它通过文件工具实际读到任务文件，报告的路径与教材目录相符，没有把参考成品误认为起始状态。如果读不到，先看它使用的路径和工具错误；如果无法访问文件工具，就还没有完成这个检查。

## App 与 IDE 用户怎样完成同一项检查

使用桌面 App 时，在 Codex 中打开教材文件夹并开始聊天，确认聊天所关联的工作位置。官方当前将桌面入口放在 ChatGPT desktop app 文档中；名称与旧版 App 可能不同，核对的是“选择工作位置再发起任务”这项操作，而不是旧截图的按钮布局。[桌面入口官方说明](https://learn.chatgpt.com/docs/app)。

VS Code 或兼容编辑器用户先打开教材文件夹，再打开 Codex 侧栏；如果图标未显示，可在命令面板寻找 `Codex: Open Codex Sidebar`。编辑器能显示文件，不代表 Codex 一定已读取；仍发送上面的只读任务，用返回的真实路径确认。[IDE 扩展官方说明](https://learn.chatgpt.com/docs/codex/ide)。

CLI 的启动参数、App 的权限控件与 IDE 的控件入口不相同。先找到当前会话的权限说明，选择能完成教材调查的范围；遇到拒绝，检查目标目录和请求的动作。不需要为了读一份任务书开放整台电脑。

## 为第一次实施准备两个终端

第 3 章将用一个终端保持 Codex 会话，另一个终端启动网页服务。两个窗口各自有当前目录；在第一个窗口执行 `cd`，不会替第二个自动切换。每次运行依赖相对路径的命令前，用 `pwd` 或 `Get-Location` 再确认一次。

网页服务采用 Python 3 标准库，先检查：

```sh
# macOS / Linux
python3 --version
```

```powershell
# Windows PowerShell
py -3 --version
```

如果显示 Python 3 版本即可继续。Windows 没有 `py` 但 `python --version` 显示 Python 3 时，后文可将 `py -3` 换成 `python`。若都不可用，从 [Python 官方下载页](https://www.python.org/downloads/)安装 Python 3，重开终端再检查。Node.js 与 Python 在本书中承担不同职责：前者可用于安装 CLI，后者仅提供本地静态网页；它不替你执行模型推理。

## 动手练习：留下可以继续的环境事实

在自己的笔记里写五行：入口、CLI 版本或 App 版本、教材完整路径、已实际读到的文件、当前权限。把“已运行”和“尚未完成”分开。例如，版本查询已成功，但浏览器登录尚未返回，就分别记录这两个状态。
