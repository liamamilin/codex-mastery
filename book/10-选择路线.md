# 第 10 章：什么时候直接做，什么时候先研究

你给 Codex一个小改动，它先写了三页计划；换一个陌生项目，它却立刻改代码。两次看起来都很主动，问题却相反：前者没有值得先解决的不确定性，后者还没找到要改变的对象。推进路线的价值，在于消除当前真正妨碍行动的条件。

本章沿用已经认识的 LinkShelf 与 TaskTrail，并引入下一章的离线数据案例。你会为四种处境选择下一步，并完成一次小行动。终点不是记住“复杂任务先规划”，而是能解释：为什么此刻这条路线能够增加信息或交付成果，以及什么观察会让你换路线。

## 先看已知与未知各是什么

“我不太懂编程”和“这个任务存在关键未知”不是一回事。你可能不认识每一行 CSS，但要改的文字、文件和验收动作都很明确；也可能懂 Python，却不知道一份 CSV 的重复行代表重复导出，还是两次真实活动。前一种通常可以小步修改，后一种要先确认含义。

先问三个具体问题：目标的行为是否明确？实际修改对象是否已找到？剩下的未知会不会改变实现或验收？如果都明确，且改动小、容易检查，就让 Codex直接推进。某个未知会改变结论时，把下一步对准它，而不是用一份很长的计划遮住它。

例如，LinkShelf 空列表的说明文字需要改成一句更清楚的话。你已确认这是自己的工作副本，知道何时出现空状态，也能打开页面检查。这里没有必要先调查数据库或比较三个前端框架。让它找到对应文字、局部修改，再看空态与非空态，已经能形成有效闭环。

## 四种路线，四种不同的产物

可以把当前任务放到下面这张表中。它是一种判断辅助，不是每次都要填的表格。

| 当前处境 | 有价值的下一步 | 下一步应留下什么 |
| --- | --- | --- |
| 目标、位置、检查都清楚 | 直接修改 | 可观察的小改动与实际检查 |
| 不知道入口、数据或现有行为 | 先调查 | 能指向文件的事实与未确认项 |
| 某个假设决定路线，但还没证据 | 做最小实验 | 具有区分力的输入、结果与判断 |
| 目标较大，成果可逐段独立使用 | 分阶段推进 | 每阶段可运行、可验收的结果 |

TaskTrail 适合说明调查路线。第一次接手时，你还不知道 `--data` 从哪里解析，直接加筛选可能改错文件；第 7 章的事实简报补上这些信息。调查结束后就应转入实施，不必每天重新写同一份项目概览。

CSV 案例适合说明实验路线。你知道要做摘要，但空值应算零还是排除、重复应算几次，会改变总数。先用四条能手算的记录验证规则，比立刻生成长报告更快暴露差异。数据含义仍需人确认；程序跑通不能代替这个决定。

LinkShelf 从收藏、检索到备份，则适合分阶段。每一段可以有独立结果，读者不用等到标签、导入、云同步都做完才能保存第一条链接。第 12 章会把这样的路线写成真正可检查的里程碑。

下面把目标模糊、统计口径未知、边界明确和补丁无效四种情境放在一起比较。选择下一步后阅读理由，再用重置重新作答。这是浏览器内的教学判断练习，不调用 Codex，也不会对真实项目自动诊断。

## 在一次小任务中使用判断

如果你已完成第 3 章，可在**自己的 `my-linkshelf` 副本**做下面的练习；不要修改教材参考成品。将此文字发给拥有该副本写入权限的 **Codex 输入框**：

```text
请把空列表的说明改为：
“粘贴一个网页地址，留下你的第一条学习线索。”
先确认当前目录与实际空状态入口，再做局部修改。
不改保存、读取、搜索和删除逻辑，不增加依赖。
修改后说明位置；可执行的检查请执行，
浏览器中空列表出现、添加后隐藏、删空后再出现由实际操作确认。
```

这个任务仍有一次定位，但没有要求完整研究。定位服务于具体修改，范围足够小时可以在同一过程中完成。若你的页面根本没有空状态，则关键条件发生了变化：先说明现有行为与最小新增范围，不要假装只替换了一句话。

在第二个操作系统终端进入**教材根目录**，启动自己的副本：

```sh
# macOS / Linux；Windows 将 python3 换成 py -3
python3 -m http.server 4174 --bind 127.0.0.1 --directory my-linkshelf
```

先停止占用 4174 的旧服务，浏览器打开 `http://localhost:4174/`。只删除本次练习新增的样本，不清空已有个人收藏；已有数据时可使用另一新副本和专用存储键。终端按 Ctrl+C 停止服务。参考成品与自行生成页面的结构可以不同，验收按行为判断，不能只检查字符串是否进入源码。

## 路线可以在事实改变后切换

假如你让 Codex直接改空状态，结果发现同一段文字由三个入口生成，且当前状态判断有冲突。此时转为短调查是合理的，不必为了遵守原先“直接做”而盲改。反过来，若已找到唯一入口，继续研究界面体系就没有增加价值，应回到局部实施。

更大的任务也可以先直接做一小段。阶段计划并不意味着禁止行动；它要帮助确定现在交付什么。实验也不是拖延实施的别名：必须明确什么结果支持继续，什么结果需要换办法。只有“先试试看”而没有判断条件，很容易演变成无止境尝试。

可以这样介入：“现在已经确认入口和规则，请结束调查，完成这一条使用路径。”也可以反过来说：“这个未知会改变统计口径，先暂停完整报告，用四行数据比较结果。”两句话都解释了为什么改变路线，而没有简单用“快一点”或“谨慎一点”代替判断。

## 动手练习：给四个请求选下一步

为下面每项选一种优先路线，并说出下一步要拿到的证据：

1. 自己的链接工具中，一句已定位的提示语需要改写，原功能正常。
2. 一个陌生 Python 工具显示空列表，你还不知道它读取哪个文件。
3. CSV 中出现重复记录，直接相加会改变总数，但记录含义未确认。
4. 希望链接工具同时具有检索、标签、导出与导入，当前只有基础收藏。
