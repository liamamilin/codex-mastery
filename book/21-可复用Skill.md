# 第 21 章：让有价值的方法成为 Skill

第一次处理 CSV，你需要说明空值怎样算、重复怎样处理、报告放哪里。第二次换一份同类数据，又从头解释这些事情。如果这套方法已经实际可用，重复描述就开始消耗注意力；但把整段聊天保存下来，也未必能帮下一次任务。

Skill 将可复用的方法放进一个有名称、适用描述和正文的目录，可以按需要附带脚本、参考资料或模板。它让 Codex 在合适情境读取那套方法，不会自动替你运行脚本，也不赋予访问外部服务的权限。本章使用案例 C 制作一个最小 Skill，并检查它能否支持第二份输入。

## 先确认值得复用的究竟是什么

准备 Python 3、案例 C，以及能读取本地文件的 Codex 会话。无需账号以外的新连接、API Key 或全局安装。先看 `cases/C-csv-insight/README.md`，理解四字段和本案例口径。

这里有两种不同的复用：`report.py` 负责确定性解析、统计和写文件；Skill 负责指导什么时候使用它、怎样确认输入与口径、如何独立核对、失败时怎样报告。若你的重复工作只是运行一条已知命令，脚本入口就够了。只有需要反复作出这些工作判断时，Skill 才开始有价值。

不要把某次访问总数写成永恒规则。2155 是当前样本的结果，不是所有报表应有的答案。也不要把某次错误变成“每次先做五轮审查”：保留真正影响决策的约定，删去没有帮助的仪式。

## 一个文件，先把边界讲清楚

本仓库示例位于 `extensions/csv-report/SKILL.md`。它的元数据是：

```yaml
---
name: csv-report
description: 为本教材 CSV Insight 案例生成并核对离线渠道汇总；适用于用户指定该案例数据或相同字段的报表任务，不用于任意 CSV 清洗、因果分析或预测。
---
```

正文保留定位案例、确认输入输出、使用已有脚本、核对口径、独立检查和交付范围。它没有把案例的整份代码复制进来，也没有发明另一套汇总实现。后续脚本更新时，应同时检查这些指引是否仍准确。

`name` 和 `description` 帮助发现与选择，完整正文按需要加载；这些结构与激活方式按 **2026-10-25** 的 [OpenAI Build skills 文档](https://learn.chatgpt.com/docs/build-skills)核对。技能描述若写成“处理所有文件与所有项目”，就很难正确选择；若塞满实现步骤，又会在还没用它时占据不必要上下文。

这个示例的存放位置有意选在 `extensions/`，供读者检查与修改。**它不属于本仓库已经安装的自动发现目录**。文件存在、格式有效、当前会话实际读取、未来会话自动选中，是不同状态，不能混写为“安装成功”。

## 先显式读取，再做一次实际复用

将下面任务发给 Codex，路径从教材根目录解析：

```text
请读取 extensions/csv-report/SKILL.md 并按其中流程处理案例 C。
输入是 cases/C-csv-insight/input/activity.csv。
输出选择一个新的练习报告路径，不覆盖我需要保留的结果。
先确认当前脚本与口径，再生成并独立核对。
报告实际命令、关键数值和未验证范围，不安装全局 Skill。
```

这是一条可以在能读文件的会话中使用的明确任务，即使该客户端尚未提供技能选择器，也能执行方法。它是显式加载文件的复用，不宣称已经验证原生自动触发。

案例 C 的运行目录是 `cases/C-csv-insight`。在操作系统终端可观察对应步骤：

```sh
python3 -B report.py --input input/activity.csv --output output/skill-full.md
python3 -B verify_totals.py --input input/activity.csv --report output/skill-full.md
```

Windows 把 `python3` 换成 `py -3`。同意这个新输出路径后再执行；若已经有同名成果，另选名字。完整样本按约定计入 21 条，访问 2155、注册 267，空值排除 2 条、重复排除 1 条。要同时看到独立核对结果，不能只读生成脚本的成功提示。

然后给同一会话第二项任务：沿用 Skill，改处理 `input/probe.csv`，使用另一个输出 `output/skill-probe.md`。这份小输入预期访问 18、注册 3，计入 2 条、空值 1 条、重复 1 条。观察它有没有仍引用上一次输入、沿用旧总数，或漏掉独立核对。这些实际分歧比询问“这个 Skill 好不好”更有用。

本项目已按这套指引读取案例并实际运行两份输入的生成与独立核对，结果与上面一致。完整输入还进行了重复字节比较。相关命令与限制在 `extensions/verification.md`，没有运行新的付费模型评测或声称所有客户端都会自动发现本技能。

## 格式有效之后，还要看行为

本示例使用 `skill-creator` 的验证脚本实际检查，返回 `Skill is valid!`。它说明元数据、命名与结构符合检查规则，不证明所有决策正确。读者若有该技能，可以请它验证自己的副本；没有也可先人工核对元数据与引用路径，不必为了练习安装一个庞大环境。

行为上重点检查三处：它是否识别任一必需字段空缺应排除整行；是否把非法日期或数值格式当作整次失败，而非偷偷补零；是否保留旧输出并说明本次失败。这里的策略来自案例约定，不可擅自套用到别人的业务数据。换数据领域时先核实含义，再决定复用哪些部分。

如果第二次仍要补很多解释，先判断是描述没说准、指引遗漏关键知识，还是根本不属于同类任务。只改导致当前分歧的那一处，不要把每次聊天里的临时要求都追加进技能正文。

## 需要自动发现时，再选择安装范围

当期官方文档将项目技能位置列为 `.agents/skills`，用户级位置列为 `~/.agents/skills`。不同版本与管理环境可能有额外兼容位置，应看当前客户端文档，不从本示例的 `extensions/` 位置推断自动加载规则。若只服务一个练习，优先在你自己的工作副本考虑项目范围，避免影响所有项目。

本章没有替你复制到这些位置。若你决定安装，可让 Codex 先检查该目录是否已有同名技能，说明具体写入位置与发现方式，再做有范围的复制。不要覆盖已有版本，也不要把安装权限误当成发布或上传数据的授权。技能和工具的职责区别可继续阅读 [OpenAI Skills 概念说明](https://developers.openai.com/plugins/concepts/skills)。

## 动手：留下一份真正减少解释的方法

在副本中精简 `csv-report`，保留对你下一次任务有用的信息。用完整样本和小样本各做一次，记录是否需要额外纠正，以及哪一句指引产生了实际作用。再拿一个字段不同的 CSV 问它是否适用，观察它是否先核实，而不是直接套口径。

完成标准是一份短技能、两次真实执行结果与准确的使用状态。可复用的价值来自减少重复判断、保留关键约定，并在不适用时停下来，而不是让一个文件承担所有未来任务。
