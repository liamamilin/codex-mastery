# 导读：把想法带到可验证的成果

你可能已经见过 Codex 写代码、解释报错，甚至连续工作很久。真正困难的时刻往往出现在后面：它说完成了，你却不知道如何检查；它修改了很多文件，问题仍然存在；新会话开始后，之前已经确认的事情又被当成未知。

本书从这些处境出发。学完之后，你应当能够接住一个陌生任务，让 Codex 获取必要事实，选择合适的下一步，完成一份可使用的成果；遇到偏差时，知道怎样改变路线，最后保存足够的状态，让工作能够继续。你会逐渐读懂代码，但起步时不需要会编程。

这里把“驾驭”理解为一种判断能力。你无需逐条指定 Codex 的每个动作，却需要知道目标在哪里，什么证据足以支持继续，以及什么时候应当介入。这种能力比记住某个菜单的位置更耐用。

## 第一趟学习，只完成一个小闭环

建议第一次按顺序阅读导读与第 1—3 章。第 1 章训练观察：分清它说了什么、实际查了什么、文件有没有变化。第 2 章把工作位置和工具准备好。第 3 章让你亲手做出 LinkShelf，一个在浏览器中添加和保存链接的小工具，并检查刷新之后的数据。

这三章的终点很具体：你的电脑上有一个独立练习目录，里面有可打开的页面；你能新增一条链接，刷新，删除，再刷新；你能解释哪些行为亲自看过，哪些还没有检查。页面颜色与书中截图不同不影响达成这个终点。截图的作用是帮助你找到界面，不是要求模型生成同一张脸。

第一趟结束后，再沿着完整课程深入。全书规划为八个部分、二十八章：认识执行搭档；把想法变成工作；调查上下文；选择推进路线；验证与交付；诊断和纠偏；扩展与复用；长期任务与毕业实战。站点的[课程目录](./curriculum.md)会明确区分已可阅读的正文与待制作章节。目录中的一个标题不能代替已经写成的教材。

## 一本书，三处工作空间

阅读时，你会在三个地方来回切换。**教材网站**提供讲解、图解和交互判断练习；**操作系统终端**接受短命令，例如查看目录、启动本地网页；**Codex 的输入框**接受自然语言任务，让它调查、修改或解释。代码块前会写清楚应该在哪里输入。

终端（terminal）可以理解为用文字操作电脑的窗口。macOS 可打开“终端”，Windows 可打开 PowerShell。你不用先学完命令语言，只需在给定目录逐条运行书中的命令。`cd` 表示切换目录；路径表示文件在电脑中的位置。遇到这些词不用硬记，第一次真正需要它们时，第 2 章会带你验证。

网站中的交互组件运行在浏览器里。选择“下一步”后出现的情境是教学演示，不会调用你的 Codex，不会修改你的本地案例。真正的实验需要你把任务发送给自己已登录的 Codex，并观察实际文件与浏览器结果。交互题答对，说明你理解了一种判断；本地案例通过，才说明你完成了那次操作。

本书主要采用 Codex CLI，也就是在终端使用的入口。App、IDE 扩展和云端在工作位置、工具与权限上可能不同。你可以用自己熟悉的入口完成同一任务，但应先确认它连接的是哪个目录，能否读文件、执行命令和修改文件。界面没有出现书中的控件时，先查入口差异，不必为了匹配截图反复重装。

## 先拿到教材源码，再决定从哪里开始

在线阅读不需要安装本网站的开发依赖。要运行案例，可打开[本书 GitHub 仓库](https://github.com/liamamilin/codex-mastery)，选择 **Code → Download ZIP**，解压到专用学习目录。下载的是源码包，网页本身不会自动出现在你的电脑上。解压后找到同时包含 `book` 和 `cases` 的那一层文件夹，这就是下文说的“教材根目录”。

主要文件按用途组织：`book/` 是中文正文；`cases/A-linkshelf/starter/` 是第一项练习的起点；`cases/A-linkshelf/solution/` 是可运行的参考成品。案例说明在 `cases/A-linkshelf/README.md`，在线入口见[实战实验室](./labs.md)。后续案例随课程扩展加入，不能假定尚未提供的目录已经存在。

第一种学习方式是从 `starter` 复制一份自己的练习目录，再给 Codex 目标，让它完成实现。第二种方式是直接运行 `solution`，先摸清“完成以后应该是什么感觉”。两种方式都有效。只想先体验成果，可以先跑参考成品；想训练指挥能力，需要回到自己的副本，经历任务、执行、验收与反馈。

不要把公司的项目或个人唯一一份资料当作第一块练习场。使用独立目录，是为了让你可以放心试验、比较和重新开始。教材中的链接数据也是虚构样本，无需导入真实收藏。

## 用结果判断，不跟着措辞走

书中会明确区分四种证据。“官方核对”表示查阅过注明日期的官方资料；“实际执行”表示在记录的环境中运行过命令或检查；“人工待验”表示仍需要真实观察；“示意”表示为讲解构造的任务或对话。预期结果不是已经发生的日志。

例如，“网页返回了正常响应”只能证明服务提供了页面。“添加后刷新仍存在”才支持保存功能可用。如果你只试了一条正常链接，就不能顺带宣布所有错误输入都处理正确。每次只写观察能够支持的结论，反而更容易找出下一步。

产品事实也有适用范围。本轮官方资料核对日期为 **2026-10-25**，本机命令核查环境为 macOS、Codex CLI `0.154.0`、Node.js `22.21.1`、Python `3.10.13`。版本号记录的是这次制作环境，不是全体读者的最低要求，也不是“最新版”的承诺。Windows 与账号登录路径依据官方资料讲解；没有把它们写成本机实测。[附录](./附录-术语与来源.md)保留具体来源和边界。

## 开始之前，留下你的第一份判断

假设 Codex 说：“我优化了保存逻辑，应该解决了刷新丢失。”你打开页面，新增成功；刷新之后，条目不见了。此时你最可能怎样做？

1. 再发一次“请认真修好”。
2. 先要求重写整个应用。
3. 记下新增、刷新、消失的步骤，要求调查保存与读取路径。

先选一个，并用两句话解释理由。现在不必追求术语准确。把答案保存在自己容易找到的笔记里，到纠偏章节再回来看。
