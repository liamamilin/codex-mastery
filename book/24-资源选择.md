# 第 24 章：模型、推理强度、时间和成本

“把设置全部调到最强，会不会最省心？”有时更深的分析能帮你处理跨文件问题，有时等待更久只是让一个简单任务花更多资源。如果缺的是运行权限、正确数据或明确目标，提高推理强度也不能替你补上这些前提。

本章不提供固定型号排行榜。模型、可用配置、套餐与使用规则会变化；你要学会的是为当前任务选择资源，并用结果判断这项选择是否值得。完成时，你会留下一份任务配置说明，或一组有边界的小样比较；没有实际测量的地方就保留未知。

## 先区分你在调什么

模型是执行任务的基础能力；推理强度影响它投入多少分析；工具与权限决定它能获得信息、执行哪些动作；上下文决定它正在依据什么。更强的模型不能读取未提供且无法访问的文件，更多分析也不会把被拒绝的存储写入变成成功。

截至 **2026-10-25**，[OpenAI Models 文档](https://learn.chatgpt.com/docs/models?surface=cli)说明可以在相应客户端选择可用模型并调整推理，较高强度可能改善复杂任务，但通常花更多时间与 token；具体可用项取决于账号、客户端和工作区。这个关系是配置方向，不是对你手头任务的性能保证。

CLI 交互会话中的 `/model` 是当前官方文档列出的选择入口；它输入在 Codex 会话里，不是操作系统 shell 命令。App 或 IDE 用当前界面可见的模型与推理控制。先观察自己能选什么，不要照抄另一账号截图中的选项，也不要为了跟课升级套餐。

## 从任务的难点选择起点

把当前任务写成一个可检查的结果，再问难度在哪里。是材料多但规则清楚，还是需求含糊、因果路径未知？是允许快速返工的小改动，还是错误会影响许多数据的变更？验证越困难，越需要把调查、检查与人工判断算进资源安排。

| 任务 | 主要不确定性 | 可以先尝试的投入方式 |
| --- | --- | --- |
| 为已有命令补一段启动说明 | 路径与参数是否准确 | 当前默认配置，读取实际帮助与文件后核对。 |
| 按已确认口径重复求 CSV 总数 | 输入是否符合格式 | 运行现有脚本与独立核对，异常时再让 Codex 调查。 |
| 修复跨刷新删除恢复 | 状态从哪里写、从哪里读 | 先保留复现与调用路径，证据不足再增加分析投入。 |
| 陌生仓库的多文件改动 | 关联范围、兼容行为与验证缺口 | 给足调查上下文和阶段结果，按实际难点考虑更深分析。 |

这些是任务配置建议，没有暗含任何两款模型的实测比较。尤其注意第二行：减少模型调用不等于降低质量。确定性脚本已经可靠完成的部分，不必每次重做推理。

## 更深分析之前，先排除资源以外的问题

如果 Codex 一直改错文件，检查工作目录；如果它反复编造字段，检查是否提供真实样本；如果修改总是无法验证，检查环境与验收路径。这些问题不解决，再换配置也可能只是更长时间地走错方向。

可以发给 Codex：

```text
当前任务是修复删除后刷新恢复，先说明阻碍来自哪里：
缺失上下文、执行权限、证据不足，还是需要更复杂的分析？
请引用已经观察到的事实，提出最小下一步。
不要为了尝试就增加无关工具或自动切换付费资源。
```

这一步帮助你把配置变化对应到真正瓶颈。若已有足够证据只差一行保存，提升强度并不是必须；若多个数据源相互覆盖、原假设连续不符，给更多分析空间才可能有明确用途。仍然要回到可观察的检查，而不是相信设置名称。

## 比较配置时，固定题目与完成条件

若你愿意使用现有额度做比较，选一个小而有代表性的任务，准备相同起点的两个独立副本。保留同样的需求、上下文、工具边界与验收动作，只改变一个因素，例如推理强度。不要把一个已看过答案的长会话与全新会话直接当作公平比较。

记录的是完整交付过程：从开始到满足完成条件的时间、需要人工纠正的次数、实际改动、通过哪些行为检查，以及客户端真实显示的用量。没有用量明细就记“未知”；不能用回复长度猜精确 token 或金额。模型第一次回复快，但需要多次返工，未必更快完成任务。

对 LinkShelf，可用“坏网址拒绝且合法输入恢复正常”的小修改；对 TaskTrail，可用保持默认行为的筛选任务。给两份结果盲看行为与 diff，避免只因某份解释更长就判断更好。一次结果只能形成当前样本下的线索，不能推出所有代码任务的排名。

本书制作没有为本章新增付费模型基准，也没有测得某配置快多少或便宜多少。你可以完成后面的无额外调用版本练习，仍然掌握比较设计与选择依据。

## 把成本算到交付，而不只算一次回复

资源成本包括使用额度或费用，也包括等待、人工核对、返工、工具配置和合并复杂度。一个更便宜的单次响应若漏掉核心检查，可能把成本转移给你；一个复杂方案若引入不必要服务，也会留下长期维护成本。

价格与额度应按登录方式和当前官方计费页面核对，API 价格不能直接解释为客户端订阅内的一次任务价格。本章不提供跨入口换算，也不推断你的剩余额度。若需要具体预算，先明确使用入口、模型、计量方式和任务样本，再做实际估计。

同样不要把更高推理设置等同于更多工具权限。选择配置与批准外部动作是两个决定。模型输出再自信，也不能代替对发布、数据覆盖或外部发送的范围判断；这些约束应在实际任务里保持清楚。

## 动手：给一次资源选择写出依据

不增加任何模型调用也能完成第一版：选 CSV 重复汇总或删除故障，写下完成条件、主要不确定性、当前可用工具、打算用默认配置还是更深分析，以及什么现象会让你调整。为比较设计两个相同起点，列出实际应收集的指标，不填写想象数值。

若你随后自行执行比较，把测量与推断分开，补上客户端、日期、配置、实际用量边界和通过的行为。完成标准是你能解释“为何这次值得投入这些资源”，并在新证据出现时改变选择。长期有用的是这个判断过程，具体型号与设置只是在某个时间点可用的工具。
