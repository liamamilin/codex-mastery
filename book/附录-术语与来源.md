# 附录：术语、操作与来源

本附录服务于已经写成的导读与第 1—3 章。事实核对日期为 **2026-10-25**。具体入口、命令参数和账号权益可能变化，遇到差异时优先比较当前程序的帮助与对应官方文档，不根据一张旧截图推断功能不存在。

## 用得到再查的术语

| 术语 | 在本书中的意思 |
| --- | --- |
| 模型 · model | 根据已获得的信息生成内容与行动选择的模型。它的判断需要证据支持。 |
| Agent · 智能体 | 围绕目标调用工具、接收结果并继续推进的执行单元。 |
| 工具 · tool | 读取文件、执行命令、操作浏览器等具体能力；是否可用取决于当前入口与授权。 |
| Harness · 执行框架 | 组织模型、会话、工具调用、权限与反馈循环的外围系统。 |
| 终端 · terminal | 显示文字输入输出、让你运行命令的窗口。 |
| Shell | 解释终端命令的程序，例如 zsh、Bash、PowerShell；不同 shell 语法可能不同。 |
| CLI · 命令行界面 | 通过终端启动与使用程序的方式。本书前三章采用 Codex CLI。 |
| IDE · 集成开发环境 | 包含代码编辑、项目导航等能力的软件。Codex 扩展是其中的一个入口。 |
| 路径 · path | 文件或目录的位置。相对路径以当前目录为起点，绝对路径给出完整位置。 |
| 工作区 · workspace | 当前任务关联的项目位置；可读、可写范围仍由实际权限确定。 |
| 沙箱 · sandbox | 限制执行动作可访问和修改范围的机制。 |
| 审批策略 · approval policy | 决定动作在什么情况下需要额外审批的策略，与沙箱边界共同起作用。 |
| 仓库 · repository | 保存项目与版本历史的位置。下载 ZIP 得到文件，不会自动得到本地 Git 历史。 |
| Git / diff | Git 用于记录版本；diff 是两个状态之间的文件差异。后续版本管理课程将实际操作。 |
| 测试 · test | 在特定输入和条件下检查结果的方法；通过只能说明其覆盖范围内的行为。 |
| localStorage | 浏览器按站点来源保存字符串的存储能力，不是云端数据库或永久备份。 |
| 来源 · origin | 浏览器用协议、主机名和端口区分的站点身份；本书练习保持来源一致。 |
| Skill | 可复用的任务方法与资源；适用时可被 Codex 使用，具体入口随产品配置变化。 |
| MCP | 让模型宿主与工具、资源连接的协议。连接本身不等于所有操作都已获准。 |

## 前三章操作速查

下面命令输入到**操作系统终端**，除非另有说明。它们不替代正文中的前提和路径检查。

| 想做的事 | 命令或操作 | 范围 |
| --- | --- | --- |
| 查询 CLI 版本与帮助 | `codex --version`、`codex --help` | 不需要启动任务；本机实际执行。 |
| 登录与查看登录方式 | `codex login`、`codex login status` | 官方核对；本轮没有重新登录。 |
| 只读调查 | `codex --sandbox read-only` | 在教材根目录启动；最终权限以当前宿主为准。 |
| 修改工作副本 | `codex --sandbox workspace-write` | 在自己的 `my-linkshelf` 目录启动。 |
| 查看会话状态 | 在 Codex 输入框输入 `/status` | 这是 CLI 内命令，不是 shell 命令。 |
| 运行参考成品 | `python3 -m http.server 4174 --bind 127.0.0.1 --directory cases/A-linkshelf` | 在教材根目录；浏览器打开 `http://localhost:4174/solution/`。 |
| Windows 运行参考成品 | 将上一条命令的 `python3` 换成 `py -3` | 需 Python Launcher；未在本机执行。 |
| 关闭本地服务 | 在运行服务的终端按 Ctrl+C | 不会删除网页文件或浏览器已保存数据。 |
| 检查案例数据逻辑 | `node --test cases/A-linkshelf/tests/core.test.mjs` | 在教材根目录；Node 原生测试，非浏览器验收。 |

## 按症状找到第一项检查

| 症状 | 先检查什么 |
| --- | --- |
| 找不到 `codex` 命令 | 是否已安装到当前环境，安装后是否重开终端；PowerShell 与 WSL 是否混用。 |
| 找不到 `cases` | 当前目录是否是含 `book` 与 `cases` 的教材根目录。 |
| Codex 解释得很详细却没有文件引用 | 要求引用实际读取的路径与片段，区分上下文中的信息与推测。 |
| 工具提示权限拒绝 | 被拒绝的动作与目标路径；不要直接判定实现有错。 |
| 服务提示端口占用 | 是否仍开着上一窗口的服务；停止旧服务或同步改变命令与浏览器端口。 |
| 页面出现目录列表 | 参考成品 URL 是否包含 `/solution/`；服务目录是否正确。 |
| 界面可见但功能不工作 | 是否双击 `file://` 打开；改用正文中的 HTTP 地址并查看脚本错误。 |
| 换地址后记录不见 | 浏览器、协议、主机名和端口是否相同；先回到原来源。 |
| 删除后刷新又回来 | 记录完整动作，再调查删除后的存储写入和刷新时的读取；先不要增加延时。 |

## 本机实际核查与未验证边界

本轮正文制作实际执行 `codex --version`、`codex --help`、`node --version`、`python3 --version`。环境是 macOS，结果分别为 Codex CLI `0.154.0`、Node.js `v22.21.1`、Python `3.10.13`。CLI 帮助确认了 `--sandbox` 的只读/工作区写入选项和版本查询入口。查询时出现不能创建 PATH 别名的警告，命令仍返回版本与帮助；这不等于安装已经失败，也不等于已完成登录检查。

案例数据测试命令实际执行，**10 项通过、0 项失败**，覆盖新增与再次读取、删除与再次读取、输入校验、损坏数据、存储失败、搜索和导出。测试采用程序化存储对象，不等于真实浏览器权限行为已通过。案例启动、HTTP 与浏览器验收的最新记录见案例 `README.md` 及仓库 `progress.md`；本附录不把尚未补齐的人工观察写成成功。

本轮没有重新安装或重新登录 Codex，没有在 Windows / Linux 本机运行安装与交互流程，没有证明所有账号可用同一模型。网页演示中的状态、练习反馈和示意任务都不调用真正的 Codex。读者的独立完成标准仍以各章实际操作与观察为准。
