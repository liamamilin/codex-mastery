# 第 28 章：毕业实战——在陌生任务上独立驾驭 Codex

前面的案例已经教过你怎样调查、实施和纠偏。这一章不再提供完整任务轨迹。你会遇到材料不完整、基础测试不足、模型可能替你补全未知的情况，需要自己判断下一步。

毕业的终点不是得到和作者相同的程序，也不是让 Codex 从头到尾没有失败。你应当能够解释目标，提供必要材料，组织一次有效执行，用证据判断成果，处理一项偏差，并留下别人可以继续的位置。案例 E 为此准备了两个陌生选题，默认选择会议记录整理，也可以选择文本工具维护。

## E1：离线会议记录整理助手

题目位于 `cases/E-capstone/e1-meetings/`。输入是 `input/` 中四份虚构 Markdown 纪要，任务约定在 `TASK.md`。团队想知道形成了什么决定、还有哪些行动、负责人和期限是什么，并能回到原文核对。

你要交付一个可重复运行的本地整理工具、结构化结果与可阅读摘要。内部实现和输出格式由你决定，不需要网页、账号或在线服务。四份材料是独立输入，不得为了程序方便删除或改写有歧义的句子。

这道题的困难在事实边界。参与者中有同名者，某些行动没有负责人；有一份纪要未注明会期，出现相对日期；后续会议又取消或调整了先前事项。输出中缺失负责人或无法确定的绝对截止日期必须填“未注明”，同时保留必要原话。不能从电脑当前日期、文件名或参会顺序补答案。

每条结论需要相对源路径和从 1 开始的行号，跨行内容可用范围；一项变更涉及几处原文时，应能沿来源解释。明确取消的行动不能继续列入有效待办，但取消事实仍应可追溯。相似措辞不一定是同一事项，建议也不等于已经形成决定。

这些是验收边界，不是提取算法。怎样调查、怎样组织字段、先验证哪个风险，都由你与 Codex 判断。不要先读教师区，再把答案包装成独立完成。

## E2：维护一份陌生文本工具

替代题位于 `cases/E-capstone/e2-texttool/starter/`。这是一个 Python 标准库 CLI，读取 UTF-8 文本，输出 `paragraph_count` 和 `paragraphs`。目录提供源程序、含糊问题报告、两个样本和两条基础测试。

你要查明为什么部分笔记的段落统计与预期不同，做最小修复并补上有效回归。输入中的非空行必须按原顺序保留，段内换行不应该全部变成段落分隔，重复内容也不能被自动去重。题面会说明空白与输出边界，但不会告诉你代码该改哪一行。

制作时，起点的两条基础测试已经实际通过，CLI 可以运行；这不表示题目已解决。它们覆盖普通文本与空输入，问题报告所涉及的其他条件仍需读者调查。本题没有参考修复版，也没有故意让基础测试长期变红来替你标出答案。

读者只需要 Python 3.9 或更新版本，不需要安装依赖、获取 API Key 或开放网络。具体运行命令在起点 `README.md`；调查前先确认实际目录和输入，不拿其他案例的测试证明这一题。

## 准备独立工作位置

从教材根目录复制一个尚不存在的副本，原始材料留作对照。命令属于**操作系统终端**，不是发给 Codex 的指令。以下两项选其一：

```sh
# macOS / Linux
cp -R cases/E-capstone/e1-meetings my-meeting-lab
cp -R cases/E-capstone/e2-texttool/starter my-text-lab
```

```powershell
# Windows PowerShell
Copy-Item -Recurse cases/E-capstone/e1-meetings my-meeting-lab
Copy-Item -Recurse cases/E-capstone/e2-texttool/starter my-text-lab
```

已有同名目录时改用新名称，后续路径也相应修改。到自己的副本中打开 Codex，保留你实际采用的任务说明。这里不提供第一条提示词的标准答案，因为识别目标、材料和未知，本身就是考核的一部分。

不熟悉编程的读者可以选 E1，让 Codex 负责程序实现，你负责原文抽查、未知判断与验收。熟悉代码的读者也不能跳过这些判断：一个运行成功却编造负责人和日期的工具，仍未完成任务。

## 交付的是成果与判断

提交内容分为四组即可。第一组是实际产物：E1 的工具与输出，或 E2 的修复与新增检查。第二组是复现与运行方式，包含必要环境、输入位置和输出位置。第三组是验证记录，说明执行过什么、看到了什么、哪些未覆盖。第四组是纠偏与接续说明，解释一项原判断如何被新证据改变，以及下一次从哪里继续。

不需要记录每句对话，也不要求模型故意先失败。发现自己的提取规则把建议当成决定，再用原文修正，就是有效纠偏；发现基础测试没有覆盖真实输入，补上能揭示差异的检查，也是一项判断调整。若你引用了教师区或外部资料，如实记录范围即可，不必把参考伪装成独立推导。

请保留至少三条值得抽查的边界。E1 应能回到原文定位；E2 应能用具体输入说明差异。不要只报告“所有检查通过”，而应让另一个人能够照着你的材料复查一项关键结论。

## 用七个观察判断自己是否掌握

首先，目标是否清楚：你能否用自己的话说出解决谁的什么问题，哪些结果不在本轮范围？其次，上下文是否可靠：说明中的现状来自文件、运行、使用者，还是模型推测？

再看推进路线：你的第一项行动是否针对关键未知，后续是否根据观察调整？执行本身产生了什么可用产物，还是只留下讨论？验证有没有对准目标版本和边界，而不只是程序启动？

最后检查纠偏、解释与接续：遇到偏差时是否改变了没有依据的假设；结论是否承认未知；新会话能否定位当前结果、证据和下一步。这些维度互相关联，无需给自己制造一个精确总分，但任何核心使用路径失败都不应被漂亮格式抵消。

如果你能解释哪些部分已可用、哪些仍待验，并留下可继续的真实状态，就已经在使用本书的方法。若最终目标尚未达到，继续工作或按[第 19 章](./19-路线调整.md)合理调整范围；“知道没完成”是准确判断，仍不能当作任务已经完成。

## 验收时保留一点陌生性

可以让没有参与实现的人选一条原文或一份文本检查结果，也可以在自己的输入副本中只改变一项事实，再重复运行。观察输出是否随之产生可解释的变化，原输入和其它无关记录是否仍完整。不要把事先背过的几条固定输出当作全部能力。

教师审阅提示在 `cases/E-capstone/teachers/README.md`，含边界剧透，没有完整实现。建议先保存自己的提交再阅读。发现遗漏后，可以补充第二版验证，清楚记录“首次未覆盖、后来补齐”，不需要抹掉真实过程。

## 给未来的自己留一个入口

毕业记录最后保留三句话：这次最有价值的判断是什么；哪条经验值得放进[个人手册](./27-个人工作手册.md)；下一次遇到陌生任务，准备从什么观察开始。

你带走的不是一套必须照抄的提示词，而是把意图带到事实、行动、证据和可继续成果的能力。这套循环可以在下一项没见过的工作中重新开始。案例材料与全部源码入口见[实战实验室](./labs.md)。
