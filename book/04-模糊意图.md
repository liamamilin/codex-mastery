# 第 4 章：当你还不知道自己真正想要什么

做出 LinkShelf 以后，你可能又有了一个愿望：“我想把它做得更好用。”这句话是真的，但不足以决定下一项修改。收藏入口费事、资料不好找、保存以后不再阅读，都可以被称为“不好用”，它们却需要不同的行动。

如果让 Codex 立刻实现，它会替你填补这些空白。可能增加标签、推荐、登录和同步，最后功能越来越多，你仍然不知道最初的麻烦是否减轻。本章练习把未知需求转成一次小探索，完成时拿到的成果是：一个有依据的优先方向，以及一项知道为什么要做的下一步。

## 先把任务从“开发”改成“认识选择”

目标尚未明确，不意味着不能开始。此刻能够完成的工作，是把可能的使用场景摆在一起，让你作比较。本轮要调查教材参考成品，请在**教材根目录**打开 Codex；若上次停在 `my-linkshelf`，先切回含 `book` 与 `cases` 的那一层并核对位置。参考[第 3 章](./03-第一次成果.md)的目录说明，在 Codex 输入框发送：

```text
我已经能在本机使用 LinkShelf，但“更好用”指的是什么还不清楚。
请先不要修改代码。围绕快速收藏、快速找回、定期回顾，
各提出一个具体使用场景和一个小尝试。
先只读查看 cases/A-linkshelf/solution 的实际能力，
区分现在就能试的行为与需要新增的功能。
请帮我缩小选择，不要一次制定完整产品规划。
```

你给它的完成状态发生了变化：这次要得到有差异的选择，不是更多代码。只读调查也有作用，能防止讨论建立在不存在的标签、阅读记录或提醒系统上。

下面是为教学整理的候选比较，并非一次真实 Codex 对话的逐字记录。

| 方向 | 主要困扰 | 当前可以怎样试 |
| --- | --- | --- |
| 快速收藏 | 看到网页时，输入与整理让人放弃保存 | 连续保存三条，观察卡在复制网址、填写标题还是点击保存 |
| 快速找回 | 记得存过，却记不清完整标题 | 用现有的标题或网址搜索，尝试不同记忆线索 |
| 定期回顾 | 保存之后，很少重新打开 | 手动挑三条并安排一次回顾，先判断回顾是否有价值 |

第三种方向当前只能做手工尝试。参考成品没有已读标记、最近阅读时间、提醒或自动回顾功能。手动把一条记录选来再看，可以了解使用价值；它不能被描述为“回顾功能已经实现”。同样，存在搜索框只证明有一个入口，搜索是否符合你的记忆方式，还要实际试。

## 选择一个最便宜的信息来源

假设你经常记得“那篇终端文章”，却忘了完整标题。先选快速找回，因为现有成品已经提供标题和网址搜索，测试它无需新增功能。我们要了解的是：你自然想到的线索，是否出现在已保存的字段里。

沿用参考成品，在教材根目录的**操作系统终端**运行下列命令。已有服务时继续使用，不要再占用同一端口。

```sh
# macOS / Linux
python3 -m http.server 4174 --bind 127.0.0.1 --directory cases/A-linkshelf
```

```powershell
# Windows PowerShell
py -3 -m http.server 4174 --bind 127.0.0.1 --directory cases/A-linkshelf
```

浏览器打开 `http://localhost:4174/solution/`；操作结束，在提供服务的终端按 Ctrl+C 停止。Python 检查与替代命令沿用[第 2 章](./02-工作环境.md)。这次不运行 `my-linkshelf`，因为你的基础版未必包含搜索，我们需要一个能力已知的试验对象。

不要清除已有收藏。新增三条虚构样本：标题“本章·终端学习”，网址 `https://example.com/terminal`；标题“本章·研究清单”，网址 `https://example.org/intent-04`；标题“本章·设计参考”，网址 `https://example.net/ui`。网址用于辨认记录，不需要访问其中内容。

在“搜索标题或网址…”中先输入“本章·终端”，检查终端样本出现，另两条样本隐藏。再替换为 `example.org/intent-04`，检查研究样本出现。接着输入 `intent04-absent-key`，应看到无匹配反馈。最后清空搜索，三条样本都应重新显示，原有收藏也仍在。如果此前保存过相同关键词，总结果数可能增加；判断时先核对本章三条的显示与隐藏。

这四次操作分别检查标题线索、网址线索、没有命中的情况，以及筛选是否只是改变显示。若清空后记录没有恢复，需要先调查行为正确性，不能继续用这份结果判断搜索是否有用。

## 正确、有用、值得投入，是三次判断

第一层是功能是否正确。编写本章时，实际调用了案例中的 `filterLinks`，上述三条样本在四次查询下分别返回终端一条、研究一条、零条、全部三条，原数组数量保持三条。这是数据逻辑的执行结果，不等于本章全部浏览器操作已经替每位读者验收。

第二层是它能否帮助你。遮住三条完整标题，凭记忆说出自己会搜索的词，然后实际输入。如果想到的是“终端”，现有标题就可能足够；如果想到“那篇同事推荐的文章”，而标题和网址都没有“同事”一词，搜不到并不能直接判定程序有错。它说明你的线索没有被记录。

第三层才是下一项投入。你可以试着给新收藏写更清楚的标题，再重复一次找回；这比立即设计自动分类系统更小，也能区分“标题习惯需要改善”和“确实缺少备注字段”。一次三条样本只能支持小范围判断，不足以证明几千条收藏下仍然好用。

这三层不要混成一句“搜索通过，所以产品成功”。功能正确由操作支持，使用价值需要你实际使用，继续投资则还要比较成本与当前需求。

## 哪些事情交给 Codex，哪些需要你回答

读取现有字段、解释过滤方式、提出三组样本，这些是材料足够时可以直接推进的工作。决定“我更在意少输入一次，还是以后更容易找回”，则需要你的真实偏好。Codex 可以帮你把取舍说清楚，无法从文件里推导出你的生活习惯。

因此，不必让它为每个样式和变量名都来询问你；也不要让它默默把个人优先级当成事实。你可以说：“技术细节按现有项目组织；若要增加需要额外账号、付费或公开发布的方案，先说明必要性，我再决定。”这是一项任务范围安排，不代表文字会自动改变工具权限。

如果所有方向都不像你的困扰，补充一段真实情境即可。例如：“我通常在手机看到文章，晚间在电脑整理。”这会暴露当前本机收藏不跨设备同步的限制。下一步应先比较手机收集与电脑整理的替代办法，而不是继续优化电脑上的搜索按钮。

## 根据试验改变路线，保留有效成果

试完之后，把观察发给 Codex。以下是**示意反馈**，请用自己的实际结果替换：

```text
三条样本的标题和网址筛选都符合预期。
但我自然想到的词是“同事推荐”，现有记录里没有这个信息。
请比较“保存时写更明确的标题”和“新增一项可选备注”两条路线。
说明各自最小尝试和需要观察的结果，先不要改代码。
保留已经可用的新增、删除和本地保存行为。
```

这样的转向没有否定前面的成果。你保留了真实可用的部分，也把“体验不满意”落到具体信息缺口上。如果写清楚标题就已解决问题，这次最好的结果可能是暂时不开发新功能。

## 动手练习：得到一项更清楚的下一步

用自己的三条虚构收藏重复试验。写下一个自然想到却搜不到的线索，判断它是输入拼错、实现错误，还是信息根本没有记录。再让 Codex 提出两个不同的小尝试，选一个说明为什么现在值得做。
