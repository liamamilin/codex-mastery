# 案例 A · LinkShelf 个人链接收藏工具

用一个能看见结果的小工具，练习把模糊意图变成范围、实际修改和可重复验收。本案例不调用 Codex 服务：真正的 Codex 协作发生在你自己的工作目录；参考工具的添加、搜索、删除和保存都在浏览器里执行。

## 从哪里开始

| 入口 | 用途 |
| --- | --- |
| `starter/` | 独立干净起点：最小页面与 `TASK.md`，没有收藏功能，供你与 Codex 一起完成。 |
| `solution/` | 可直接运行的参考成品：A1 基础功能、关键词搜索、JSON 导出。 |
| `tests/core.test.mjs` | 无第三方依赖的数据逻辑与存储错误测试。 |

建议将 `starter/` 的文件复制到仓库根目录的 `my-linkshelf/` 再练习，保留参考成品作对照。第 3 章使用这个工作副本；不要一开始就让 Codex 将答案复制过来。

首版要完成：输入标题与 `http/https` 网址 → 保存并显示 → 刷新后仍在 → 删除 → 刷新后不再出现。你将练习界定范围、给出材料、让 Codex 实施、观察结果，以及区分“界面变了”与“数据真正保存了”。搜索与导出是参考成品的额外能力；**此阶段没有导入、标签、账号或云同步**。

## 准备与运行

需要现代浏览器，以及 Python 3（仅用于启动本地静态服务）。测试另需 Node.js 18 或更新版本；运行网页本身不需要 Node、npm、数据库、网络 API 或安装依赖。

先打开操作系统终端，进入**这个教材仓库的根目录**。不要把下列命令当作发给 Codex 的自然语言提示词。

macOS / Linux 先检查：

```sh
python3 --version
```

Windows 使用已安装的 Python Launcher 检查：

```powershell
py -3 --version
```

应显示 Python 3.x。若提示找不到命令，先完成 Python 3 安装，重新打开终端再检查；Python 可执行文件的实际名称因安装方式而异。

**打开参考成品**，在仓库根目录执行：

```sh
python3 -m http.server 4174 --directory cases/A-linkshelf
```

Windows 对应命令：

```powershell
py -3 -m http.server 4174 --directory cases/A-linkshelf
```

终端保持运行，浏览器地址栏输入 **<http://localhost:4174/solution/>**。应看到“把值得回来的网页，放在一起。”和一个空链接架。路径中的 `solution/` 不可省略，否则会显示目录列表。按 **Ctrl+C** 停止终端中的服务。不要靠双击 HTML 的 `file://` 地址验收此案例；它和 HTTP 页面的模块加载、存储来源规则不同。

**运行自己的工作副本**，另在仓库根目录执行 `python3 -m http.server 4174 --directory my-linkshelf`，浏览器打开 `http://localhost:4174/`。先停止正在使用 4174 端口的前一个服务。Windows 同样将 `python3` 换成 `py -3`。

## 与 Codex 一起做

先读 `starter/TASK.md`。可将下面这段作为第一条任务（自然语言，发给 Codex）：

> 我想做一个个人链接收藏工具。工作目录是 my-linkshelf，目前只有最小页面。先确定第一版范围和验收动作，再实现输入标题和 http/https 链接、保存、列表、删除和刷新后持久化。只用原生 HTML/CSS/JavaScript，不做账号与云端服务。空输入和坏网址要反馈；保存失败不能显示为保存成功。请说明怎么启动和验证，不改动其他案例目录。

生成代码后，你亲自按下一节操作。若某一步失败，把**实际动作、网址、可见结果**告诉 Codex；例如“点删除时条目消失，但刷新后回来”，比“删除坏了”更能缩小调查范围。界面不需要和参考图相同，完成状态需要相同。

## 可重复验收

在同一个浏览器、同一个 `http://localhost:4174/solution/` 页面完成下列操作。若已有自己的收藏，先“导出 JSON”保留备份，验收时只删除本轮新增的条目。

1. **空状态**：首次打开无收藏时，看到填写标题和网址的引导；“导出 JSON”不可用。
2. **新增**：标题填“示例网站”，网页地址填 `https://example.com`，点击“保存到链接架”。应看到该标题和网址，数量增加；表单清空，出现已保存反馈。
3. **刷新**：使用浏览器刷新，刚才条目仍在。关闭并重新打开同一地址，也应能从当前浏览器读取记录；清理站点数据或无痕窗口退出后不保证保留。
4. **搜索**：再添加“学习资料” `https://example.org/learn`。在“搜索标题或网址…”中输入“学习”，只显示“学习资料”；清空搜索，恢复全部。搜索不存在的词，出现无匹配的反馈，不会删除收藏。
5. **删除与回归**：点击“示例网站”那一行的“删除”，然后刷新。它不再出现，“学习资料”仍在。
6. **错误输入**：标题留空保存，应提示填写标题；输入标题后将网址改成 `javascript:alert(1)` 或 `example.com`，应提示需要完整的 `http/https` 地址，数量不增加。再改成 `https://example.com` 应能正常保存。
7. **导出**：点击“导出 JSON”，检查浏览器下载列表。打开 JSON 文件，应能找到 `format: "linkshelf"`、`version: 1`、`exportedAt` 和 `links` 数组；数组中条目与当前收藏一致。导出只发起浏览器下载，不声称文件已经保存到某个固定目录。此阶段尚未实现重新导入。
8. **键盘**：用 Tab 在输入框与按钮间移动，焦点应可见；表单里按 Enter 可提交；错误后焦点回到需要修正的输入框。使用手机窄屏时表单和列表上下排列。

这里的删除不需二次确认。误删后只能从已导出的备份中手动找回地址；本阶段没有撤销或导入按钮。

## 数据、失败与安全边界

- 收藏保存在 localStorage 的独立键 `codex-mastery:linkshelf:a1:v1`，不读取或清除其他应用的键。它属于**当前浏览器与站点来源**：协议、主机名、端口任一变化，看到的数据都可能不同。`localhost` 与 `127.0.0.1`、4174 与 4175 不是同一来源。同一来源下的路径不同，仍可能共用这个键；为自己的工作副本选用独立键，或明确知道两者可能共享收藏。
- 数据不是云备份，不跨设备同步。浏览器清理、存储策略、无痕模式或用户删除站点数据都可能让记录消失。导出的 JSON 是本地备份材料，保存位置由浏览器决定。
- **先写存储，再更新列表**。若写入失败，已有列表保持原样，输入保留，页面显示“这次更改没有保存”。因此新增或删除后仍需刷新验证，不能只看当前 UI。
- 读取失败或保存数据格式异常时，暂停写入，避免悄悄用空列表覆盖原始数据。先在浏览器开发者工具的站点存储面板备份上述键的原始值，检查权限与格式，再刷新。不要直接清空整个 localStorage。
- 只接受 `http:`、`https:`。标题使用 DOM 的 `textContent` 显示，输入 `<b>学习</b>` 会作为文字，而不会创建 HTML 元素。链接在新标签页打开并设置 `noopener noreferrer`。这不代表目标网站可信，陌生网址仍需自行判断来源。
- 两个标签页同时修改收藏时采用各自读取的内存快照，可能互相覆盖；此轻量首版不解决多标签页冲突。练习时保持一个操作页面，修改前可刷新。

可选地检查存储失败：先导出自己需要的记录，在浏览器设置中禁用该测试站点的存储，刷新后尝试保存，观察是否出现明确错误。不同浏览器的入口和行为不同，此步骤必须在自己的浏览器实际观察；自动测试使用会抛错的存储对象验证对应逻辑，不冒充浏览器权限操作。

## 文件怎么连接

```text
solution/index.html   表单、列表、空态和可访问标签
solution/styles.css   LinkShelf 的排版、配色、响应式和系统明暗主题
solution/app.mjs      DOM 交互：提交、搜索、删除、下载与反馈
solution/core.mjs     纯数据操作：校验、读写、筛选与 JSON 序列化
tests/core.test.mjs   Node 原生测试，不依赖第三方库
```

存储格式是 `{ "version": 1, "links": [...] }`；每条记录有 `id`、`title`、`url`、`createdAt`。导出格式额外包含 `format` 与 `exportedAt`。数据格式校验失败时不会自动“修复”为新空数组，这正是为了留下调查证据。

## 常见问题

| 现象 | 下一步 |
| --- | --- |
| 终端提示端口已占用 | 先找到原来启动服务的终端并按 Ctrl+C；也可临时改端口，但这是另一个存储来源。 |
| 浏览器显示目录列表 | 参考成品需要访问完整路径 `/solution/`。 |
| 页面可见但不能保存，或脚本加载失败 | 检查是否用了 `file://` 双击打开；按上述 HTTP 服务方式重开，查看浏览器控制台错误。 |
| 换地址后收藏“消失” | 先核对浏览器、协议、主机名、端口；回到原来源检查，先不要重复保存或清理数据。 |
| 刷新后删除的条目恢复 | 记录复现动作，调查删除是否走了 `writeLinks()`，再检查实际存储值；不要只添加刷新 UI 或延时补丁。 |
| “无法读取当前浏览器的收藏” | 先备份单个专用存储键，调查权限或数据格式；不要让空状态覆盖原始值。 |
| 没找到 JSON 文件 | 查看浏览器下载列表和下载权限；导出不包含本阶段尚未实现的导入操作。 |
