# LinkShelf：你的工作起点

这里刻意没有实现收藏逻辑。先将此目录的文件复制到你自己的 `my-linkshelf/`，在那个目录中让 Codex 工作，保留 `solution/` 作为可对照的参考结果。

## 任务意图（A0）

我经常看到值得以后再看的网页，想要一个本机浏览器里的链接收藏工具。请先帮我确定首版范围和验收动作；还不确定的事情先指出来，不要立即扩展成有账号和云同步的产品。

## 首版完成状态（A1）

- 可以填写一个标题和完整的 `http://` 或 `https://` 网页地址，然后保存。
- 页面列出已保存的链接；刷新后还在。
- 可以删除指定链接；刷新后它不会回来。
- 空列表告诉使用者下一步做什么。
- 空标题、错误网址和 `javascript:` 等协议不能保存；使用者能看到原因。
- 浏览器禁止存储或写入失败时，应明确告知“未保存”，不能把只在当前页面出现的结果说成持久化成功。

先不实现账号、云端数据库、跨设备同步、标签、导入或复杂的构建工具。可以使用原生 HTML、CSS、JavaScript 与 localStorage。

## 先让结果可以检查

在修改之前，请 Codex 告诉你它准备怎样启动页面、怎样验证“新增→刷新→删除→刷新”。在同一个地址和浏览器中操作，因为 localStorage 属于当前浏览器与站点来源（协议、主机、端口）。

教材第 3 章会带你在仓库根目录运行本地静态服务。若你的工作副本目录是 `my-linkshelf/`，可执行：

```sh
python3 -m http.server 4174 --directory my-linkshelf
```

浏览器打开 `http://localhost:4174/`。Windows 已安装 Python Launcher 时，将命令中的 `python3` 换成 `py -3`。终端保持运行，按 `Ctrl+C` 停止服务。

## 自己验收

新增“示例网站” `https://example.com` → 看见该条目 → 刷新后仍在 → 删除 → 再刷新仍不在。然后输入 `javascript:alert(1)`，应看见错误提示，收藏列表没有增加。不要仅凭 Codex 回复“完成”就结束。

参考成品在 `../solution/`；自己的界面不必和参考图一模一样，只要能解释并检查同样的行为。
