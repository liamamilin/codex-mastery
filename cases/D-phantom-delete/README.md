# 案例 D · Phantom Delete：删除后为何又回来

这是一个**故意保留功能故障**的本地教学实验，不是可存放真实资料的产品。浏览器确实执行提供的 JavaScript，右侧面板确实读取当前内存与 localStorage；这里没有模拟终端，也不会调用 Codex 服务。

你的任务是复现“点击删除后消失，刷新后恢复”，用最小证据区分原因，再修复并检查相邻功能。不要先打开参考答案。

## 起点与文件

- `starter/`：教学故障版。先使用它调查，不要把缺陷当作已修复。
- `solution/`：独立参考修复版，阅读会剧透。
- `shared/`：两版本共用的安全数据读写、合成样本与 UI。
- `tests/delete.test.mjs`：既证明故障可确定性复现，也检验参考修复。

两版本分别有入口 `index.html`、`app.mjs`、`core.mjs`。`shared/ui.mjs` 负责真实操作与观察；`shared/storage.mjs` 管理读写。故障与修复的 `core.mjs` 可直接对照，最小差异只有一条持久化调用。

练习时先把整个 `D-phantom-delete/` 文件夹复制为仓库根目录中的 `my-phantom-delete/`，只在副本的 `starter/core.mjs` 实施修复。必须连同 `shared/` 一起复制。保留原始故障与参考修复用于回看，避免为了练习改坏教材原件。

## 启动

需要现代浏览器与 Python 3；运行逻辑测试另需 Node.js 18+。所有页面都是静态资源，无需 npm、数据库、API Key 或在线服务。

在**教材仓库根目录**的操作系统终端检查 Python，然后启动仅监听本机回环地址的服务：

```sh
python3 --version
python3 -m http.server 4176 --bind 127.0.0.1 --directory cases/D-phantom-delete
```

Windows 已安装 Python Launcher 时，使用：

```powershell
py -3 --version
py -3 -m http.server 4176 --bind 127.0.0.1 --directory cases/D-phantom-delete
```

浏览器打开 **<http://127.0.0.1:4176/starter/>**。参考修复版地址是 **<http://127.0.0.1:4176/solution/>**。自己的工作副本改用 `--directory my-phantom-delete`，地址仍是 `/starter/`。终端保持运行，按 **Ctrl+C** 停止；同一个端口只能运行一个服务。不要双击 HTML 用 `file://` 启动。

## 复现与取证

首次打开每个版本时，只有在该版本专用键不存在时才写入 3 条合成样本。空数组 `[]` 不会触发重新播种。如果你已经练习过，点击“恢复初始样本”，确认它将覆盖当前版本的练习链接。

1. 在 `starter/` 确认“示例网站”“学习资料”“待整理的参考”三条样本可见。
2. 点击“示例网站”那一行的“删除”。当前列表中该条目消失。
3. 点击“检查内存与存储”。右侧应显示内存 2 条，存储重新读取 3 条，并能在存储快照中看到 `sample-1`。删除本身也自动更新一次对照，手动检查用于再次读取。
4. **不要先新增其他条目**，直接使用浏览器刷新。同一地址重新载入后，“示例网站”返回。刷新会开始新的页面轨迹，旧轨迹可先复制记录。
5. 给 Codex 发送任务：

   > 我在 my-phantom-delete/starter/ 点击删除后，当前列表变为两条，但刷新后三条恢复。先不改代码。请从入口追踪删除事件、内存数组、存储写入和页面初始化读取，引用真实文件与函数。用一个检查区分“页面渲染没更新”和“删除结果没有保存”，再提出最小修复。不修改其他案例，不直接复制参考答案。

这些是**预期观察步骤**，不能替代你自己的实际运行记录。也可在浏览器开发者工具的站点存储面板中找到本案例键，对照删除前后的 JSON；不需要手动清空整个 localStorage。

### 一个容易把证据掩盖的动作

故障版的**新增**会保存当前完整内存数组。如果先删除，再新增一条记录，新增过程可能顺带把前一次删除持久化，导致刷新后看起来“又好了”。因此首轮要严格执行“恢复样本→删除→检查→刷新”，不要混入新增操作。这个差异恰好说明：复现动作的顺序是证据的一部分。

## 修复与回归

在工作副本中只修复删除的保存路径。修复后在相同浏览器和来源执行：

1. 恢复初始样本 → 删除“示例网站” → 检查两份状态都为 2 条 → 刷新 → 被删记录仍不在。
2. “学习资料”和“待整理的参考”仍在，证明没有删除错对象。
3. 新增“回归检查” `https://example.com/check` → 刷新 → 新记录仍在，旧删除不会恢复。
4. 逐条删除直到空列表 → 刷新 → 仍为空，没有自动恢复初始样本。
5. 输入空标题、`javascript:alert(1)` 或 `example.com` → 看到错误，已有收藏不变；随后换合法地址仍能保存。
6. 恢复初始样本 → 确认只有当前版本重新出现 3 条，不影响另一版本或案例 A。

如果浏览器禁止写存储，参考修复版会显示操作未完成，原列表保持不变。自动测试会用抛错存储对象验证这条逻辑；这不代表已测试每种浏览器权限设置。

## 数据边界

| 版本 | 专用 localStorage 键 |
| --- | --- |
| 故障版 | `codex-mastery:phantom-delete:starter:v1` |
| 修复版 | `codex-mastery:phantom-delete:solution:v1` |

`restoreSamples()` 只写当前版本的一个键；不使用 `localStorage.clear()`，不删除案例 A 或其他版本的数据。数据属于当前浏览器与来源（协议、主机、端口），`localhost` 与 `127.0.0.1` 不同。更换地址、浏览器或清理站点数据会影响可见记录，不是跨设备同步。

工作副本隔离了文件，不会自动隔离浏览器存储。原件和副本若先后使用同一浏览器、同一来源与同一版本键，会看到同份练习数据；“恢复初始样本”也会覆盖这份共享样本。若需要保留某次调查的数据，先记录或备份，另选端口或独立浏览器进行下一次练习。

只接受 `http/https` 地址，用户标题与快照以 `textContent` 展示；新标签页链接设置 `noopener noreferrer`。合成网址用于观察保存行为，无需真的访问目标站点。不要把不可信网页地址当作安全内容。

读取到损坏 JSON、错误版本或非法记录时，不用空样本自动覆盖；先备份本版本专用键的值再调查。仅在明确同意“恢复初始样本”时覆盖当前版本练习数据。首版不提供多标签页并发写入协调，练习时保持一个操作页面。

## 故障分支

| 现象 | 先检查什么 |
| --- | --- |
| 根目录显示文件列表 | 打开完整 `/starter/` 或 `/solution/` 路径。 |
| JS 未加载 | 确认 HTTP 服务、`shared/` 随副本完整复制、浏览器控制台的实际路径。 |
| 点击删除后没有恢复 | 确认打开的是 starter；恢复样本后直接删除并刷新，期间不新增。 |
| 页面无样本且有报错 | 先备份当前专用存储键，调查权限或 JSON 格式；不要直接清空全部数据。 |
| 空列表刷新后出现样本 | 检查是否用空数组当作“尚未初始化”；本参考只在键不存在时播种。 |
| 为何加延时没用 | 延时不改变持久化内容；取证应检查写入发生了没有。 |
